## 现象、事实、根因与影响

- 实际现象：抓包表格直接展示查询结果，旧连接排在新连接之前。
- 预期：最新建立的连接位于第一行。
- 最小复现：连续打开三条记录后查询第一页，观察返回顺序。
- 当前已验证：Store 使用 `VecDeque::push_back` 追加新记录；`query` 使用 `records.iter()` 收集后再分页；React 表格按 `page.rows` 原顺序渲染。
- 推断：无。
- 未知：无。
- 候选原因：前端排序、后端分页前顺序。源码已排除前端排序并确认后端正向迭代。
- 已确认根因：共享 Store 在分页前按插入正序收集记录，导致最早建立记录优先。
- 影响范围：抓包列表及共享 `exchange_observation_query` 的返回顺序；单条详情与事件时间线不受影响。

## 方案、任务与验收

- 最小改动：将 Store 查询迭代改为反向，再执行既有过滤和分页；前端仅补充明确表头文案。
- 最优设计：为 Query 增加可配置 sort/direction。用户只确认固定最新优先，引入公共字段和双向排序会扩大合同，暂不采用。
- 采用最小改动：以连接写入序列作为稳定建立顺序，避免依赖相同时钟时间或在前端局部排序。
