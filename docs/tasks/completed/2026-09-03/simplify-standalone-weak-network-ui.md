## 背景、目标与需求确认

当前设备网络方案在选择后同时展示透明代理、覆盖地址、十项基础参数和全部高级 TCP/IP 故障参数。
用户反馈其他使用者认为页面过于专业，并要求参考 QNET、PerfDog、WeTest 的场景优先、渐进披露思路
简化界面。用户进一步明确：弱网必须能够单独运行，不依赖代理入口；随后确认开始修改。

目标：把默认路径收敛为“选择设备 → 选择应用 → 设置常用弱网效果 → 启动”，明确告知弱网无需代理即可
运行；透明代理、覆盖范围和专家参数继续保留，但默认后置收起。

## 范围、不在范围与就绪检查

- 默认展示延迟、延迟波动、丢包率、上传限速和下载限速。
- 丢包率在 UI 使用百分比，提交时无损映射到现有整数基点合同。
- 透明代理路由、弱网覆盖范围和专家参数放入可展开的“更多设置”。
- 折叠标题必须显示已配置数量或启用状态，不能隐藏正在生效的非默认配置。
- 明确 `proxy_routes` 为空时弱网仍可独立启动；没有代理入口不得阻止弱网配置和启动。
- 保留保存、启动、应用修改、运行 owner、安全确认和 Rust 权威校验。
- 不新增场景预设及其数值；当前没有经过用户或业务证据确认的 2G/3G/4G、地铁、电梯等参数合同。
- 不修改 Rust Domain、Android Engine、Companion、Workspace Schema、MCP 或真实网络行为。
- 不修改当前工作区中另一任务正在调整的 Listener 文件。

## 需求变更记录

- 原需求：只简化现有参数层级，不新增 2G/3G/4G、地铁、电梯等场景预设，因为当时没有确认数值来源。
- 变化内容：2026-09-03 用户要求继续从网上查找现成数值模板并加入若干场景。
- 变化原因：进一步降低手工填写参数的门槛，采用 PerfDog/QNET 的“场景模板 + 自定义参数”思路。
- 用户确认：用户原话“你看看网上有没有现成数值模版 搞几个场景噻”，确认可以加入有来源的场景。
- 影响范围：新增前端场景选择和纯映射测试；不新增 Rust 字段，不改变 Profile Schema、Android Engine、
  Proxy 路由或运行时合同。
- 失效验收项：初始范围中的“不新增场景预设及其数值”被本记录替代；其他验收项继续有效。
- 新数值合同：仅采用公开、可追溯的官方预设；RTT 按本项目上/下行逐包延迟模型换算为单向固定延迟，
  Kbps 按十进制除以 8 转为 B/s；场景名称标记为“参考”，不宣称复刻真实运营商、地区、地铁或电梯。
- 新场景：参考 2G（sitespeed.io：下行 280 Kbps、上行 256 Kbps、RTT 400 ms）、参考慢速 3G
  （下/上行 400 Kbps、RTT 200 ms）、参考慢速 4G（Lighthouse：下行 1.6 Mbps、上行 750 Kbps、
  RTT 150 ms、无丢包）及完全断网（现有 100% 随机丢包合同）。
- 新验收：选择场景必须一次写入对应常用参数，选择“自定义”不得改写当前参数；之后手改任何常用参数
  都保留为自定义值；保存仍提交同一 `WeakNetworkProfile`。
- 新来源：`https://www.sitespeed.io/documentation/throttle/`、
  `https://github.com/GoogleChrome/lighthouse/blob/main/docs/throttling.md`。
- 需求重新就绪：来源、单位换算、范围和 PASS/FAIL 验收已明确；2026-09-03 15:31:29 +08:00 继续实现。

## 最小改动与最优设计

- 最小改动：重排现有 React 组件，把常用参数留在默认层，将现有卡片置于 Accordion；不改领域对象。
- 最优设计：新增 Rust 所有的弱网场景模板目录及 ViewModel。该方向需要确认场景名称、上下行语义和

- 采用最小改动；复用 HeroUI Accordion 和现有卡片/命令，不新增依赖或第二套运行路径。
