## TODO-SOCKET-CAPTURE-004：让 Socket 透明转发流量进入抓包 UI

需求状态：`待实施`

优先级：`P0`

### 已确认的问题与根因

- 透明转发当前走 `relay_bidirectional_with_progress`，只累计应用→上游服务、上游服务→应用的
  字节数并发布运行诊断，没有创建或注入 Socket 抓包上下文，因此抓包查询、事件刷新和详情 UI
  都没有可展示的数据。这不是前端刷新问题。
- 按协议转发和本机应答会经过协议处理器及现有抓包发布器；透明转发刻意绕过协议包、字段结构、
  规则与协议视图，所以不能复用现有“转发报文/本机应答”数据模型伪造一条协议报文。
- TCP `read`/`write` 的分段不是业务报文边界。一次读取可能只包含半条消息，也可能包含多条消息；
  UI 必须明确显示“字节流片段/连接流量”，不能把内部缓冲区边界称为报文。

### 目标设计

- 在 Socket 抓包模型中新增严格独立的 `TransparentFlow`（名称可在实现时按仓库约定调整）变体，
  与按协议转发、本机应答保持 closed union 隔离。该变体只保存：工作区、入口、运行代次、连接、
  双向序号、方向、已成功写出的原始字节、字节数、截断信息和时间；不包含协议包、字段结构、
  字段值、命中规则或协议视图。
- 在 proxy 的通用字节泵中定义中立、只读的“成功写出字节观察”接口；proxy 不依赖 application、
  SQLite 或 UI DTO。infrastructure 负责把观察事件适配到现有有界、非阻塞的抓包发布器，保持依赖
  倒置并避免把持久化逻辑塞进转发核心。
- 只在字节已经成功写入对端后记录对应范围。仅从源端读到但没有写出的字节不得出现在成功流量中；
  部分写入后失败时只记录实际写出的前缀，并保留关联的失败诊断；EOF 或空读取不创建空记录。
- 透明转发仍是完全透明的 byte-for-byte 路径：抓包观察不得调用协议包、Rhai、字段规则或协议视图，
  也不得修改、等待持久化或重新分块线路数据。SQLite 慢、抓包队列满或 UI 未打开时仍优先保证转发；
  若观察数据因有界容量被丢弃，必须提供可见的丢弃计数/诊断，不能静默制造“没有流量”的假象。
- 抓包列表按连接聚合展示双向累计字节和最近时间；详情按连接、方向和序号展示有序的字节流片段，
  默认提供 Hex/原始字节视图。产品文案使用“应用→上游服务”“上游服务→应用”“透明转发流量”，
  不显示 `Listener` 等实现术语，也不提供不存在的协议字段视图。
- 清空抓包、切换工作区和运行代次继续复用现有 generation/owner 边界；旧连接的迟到观察不得在清空后
  复活，也不得混入新入口运行代次。

### 实施边界

1. proxy：在双向 copy/write 成功边界发布有序观察事件，并保持 half-close、超时、取消和背压语义不变。
2. infrastructure：为透明转发注入抓包适配器，复用现有有界发布队列和 SQLite drain；新增透明流量
   持久化、分页、详情和清理实现。
3. application/Tauri：扩展严格 tagged union、分页/详情 DTO 和事件投影；透明流量字段不得借用协议包字段。
4. frontend：在现有 Socket 抓包列表和详情中增加透明流量分支、双向字节统计及 Hex 视图；按协议数据
   的协议视图和规则命中展示保持不变。

### 验收测试

- 真实 TCP 覆盖应用→上游服务、上游服务→应用、双向同时传输、粘包、拆包、大于内部缓冲区的数据、
  half-close、取消、读写超时和连接失败；线路收到的字节必须与抓包记录拼接后的已写出字节完全一致。
- 无协议包、无字段规则时透明转发仍可抓取；抓包详情只显示原始/Hex，不出现字段结构、协议视图或命中规则。
- 写失败只记录成功前缀并关联详细失败原因；读取后零写出、空流和未建立连接均不得生成伪成功记录。
- 抓包队列饱和、SQLite 暂停、UI 关闭时转发行为和吞吐不依赖抓包消费者；容量丢弃有稳定计数和可见诊断。
- 清空抓包与连接并发、停止后迟到事件、工作区切换和入口重启均不复活旧数据或串到新运行代次。
- 前端列表、筛选、分页、详情关闭/焦点恢复和窄窗口布局覆盖透明转发；定向 Rust/TypeScript 测试及
  受影响覆盖率门禁通过后，再做真实客户端与 Windows 产物验证。

## TODO-EXTERNAL-PACKAGE-008：支持外部软件包作为 Socket 协议处理后端

需求状态：`待实施`

优先级：`P0`

### 目标与适用场景

- 在现有内置 Rhai 协议包之外，允许第三方进程通过 WebSocket + JSON-RPC 注册“外部软件包”，为
  Socket 提供与协议包一致的报文边界识别、字段解析、报文重建和协议视图能力。
- 主要解决内置协议包不适合直接承载的能力，例如 DUKPT、厂商密码机、专用 SDK、硬件密钥、闭源算法
  或其他需要独立进程和独立技术栈的处理逻辑。密钥、算法状态及第三方内部实现均由第三方软件负责，
  Proxy 不保存、不推断也不管理。
- 第一版只支持 Socket。HTTP 外部软件包和“外部软件包 + 内置协议包”的可组合处理链暂不实现，但
  端口、领域模型和运行时选择不得把实现写死为永远只能二选一，以便后续增加有序处理链。

### 产品边界

- Proxy 启动唯一一个 WebSocket 服务，默认监听 `0.0.0.0:8765`，固定路径 `/packages`。设置页允许修改
  监听地址、端口、RPC 超时和单软件包最大并发数；监听地址或端口修改后重启应用生效。
- 服务随应用启动，不提供总开关。端口绑定失败不得阻止应用启动，也不得改用随机备用端口；内置协议包
  继续可用，设置页显示明确失败原因和预期连接地址。
- 不做身份认证和来源限制，任何能够访问该地址的第三方进程均可连接。该信任边界必须在设置页明确说明。
- 一个 WebSocket 连接只注册一个精确 `(package_id, version)`；Proxy 可同时接收任意数量的软件包连接，
  实际容量由系统资源和全局限制决定。
- 同一精确身份只能有一个在线连接，先注册者持有该身份，后续重复注册被拒绝。入口始终绑定精确版本，
  不自动升级、不自动切换到同包其他版本。
- 外部软件包与内置协议包在同一个“协议包”页面管理，不新增顶级页面或数据平面。外部项显示“外部”标志。

### 注册合同

- 每个新连接建立后，由 Proxy 在 30 秒内且仅调用一次注册方法：

```json
{"jsonrpc":"2.0","id":"register-1","method":"package.register","params":{"api":1}}
```

- 第三方返回严格 JSON 对象，结构与当前 Socket 协议包 TOML 的对象层级保持一致，但 Schema 直接内联，
  不使用文件路径，也不增加 `content_types`、`request`、`response` 或额外方向键：

```json
{
  "jsonrpc": "2.0",
  "id": "register-1",
  "result": {
    "api": 1,
    "package": {
      "id": "vendor-dukpt-iso8583",
      "name": "DUKPT ISO8583",
      "version": "1.0.0",
      "description": "使用外部密码设备处理 DUKPT 报文"
    },
    "document": {
      "upstream": {
        "schema": {
          "id": "dukpt-iso8583-upstream",
          "title": "DUKPT ISO8583 Upstream",
          "version": 1,
          "fields": [
            {"name": "message_type", "label": "MTI", "type": "string"},
            {"name": "amount", "label": "Amount", "type": "int"},
            {"name": "icc_data", "label": "ICC Data", "type": "blob"}
          ]
        },
        "display": "render_message"
      },
      "downstream": {
        "schema": {
          "id": "dukpt-iso8583-downstream",
          "title": "DUKPT ISO8583 Downstream",
          "version": 1,
          "fields": [
            {"name": "message_type", "label": "MTI", "type": "string"},
            {"name": "response_code", "label": "Response Code", "type": "string"}
          ]
        },
        "display": "render_message"
      }
    },
    "hooks": {
      "upstream": {
        "frame": "split_frame",
        "decode": "decrypt_and_decode",
        "encode": "encode_and_encrypt"
      },
      "downstream": {
        "frame": "split_frame",
        "decode": "decrypt_and_decode",
        "encode": "encode_and_encrypt"
      }
    }
  }
}
```

- `api/package/document/hooks`、上下行 Schema、`frame/decode/encode/display` 均为第一版必填项。注册边界严格
  拒绝未知键、空 ID/名称/版本、空 Schema、重复字段名、未知字段类型、缺失方法或非法方法名。
- hook/display 的值是第三方声明的方法后缀。Proxy 按所在命名空间组成实际 JSON-RPC 方法名，例如
  `hooks.upstream.frame = "split_frame"` 对应 `hooks.upstream.split_frame`。后缀不得包含 `.`；同一命名空间
  内 `frame/decode/encode` 不得复用同一后缀，不同命名空间可以复用。
- Proxy 对规范化后的注册对象计算指纹。相同 `(package_id, version)` 的内容与已保存指纹不一致时拒绝注册；
  第三方要修改 Schema、方法或含义时必须发布新版本。

### 运行时调用合同

- 上行和下行均执行同一条抽象处理链：`字节缓冲区 → frame → decode → Document → 当前阶段规则 → encode → 字节`。
  外部软件包是该处理链的一种执行后端，不复制一套规则模型、Document 模型或抓包模型。
- Proxy 持有 TCP 累积缓冲区。`frame` 每次接收当前方向的完整累积缓冲区 Base64，并返回：

```json
{"status":"need_more"}
```

  或：

```json
{"status":"complete","consumed_bytes":59}
```

- Proxy 只按 `consumed_bytes` 切出一帧，剩余字节继续保留以处理拆包和粘包。`frame` 只负责确定密文线路上的
  报文边界；例如 DUKPT 解密应由 `decode` 完成，加密应由 `encode` 完成。
- `decode` 接收单帧 Base64，返回严格的带类型 Document；`encode` 接收 Document，返回 `frame_base64`；
  `display` 接收 Document，返回 HTML，继续复用现有安全清洗、大小限制和 Hex 降级。
- Document 字段值使用 closed tagged union，避免 JSON 数字精度、Blob 与“未设置/空值”混淆：

```json
{
  "document": {
    "message_type": {"type":"string","value":"0200"},
    "amount": {"type":"int","value":"1000"},
    "approved": {"type":"bool","value":true},
    "icc_data": {"type":"blob","value_base64":"n6c="}
  }
}
```

- `int` 使用 i64 十进制字符串；`blob` 使用 Base64。字段缺失表示“未设置”，空字符串、`0` 和 `false` 都是
  已设置值。空 Document 合法；未知字段、类型不匹配、越界整数和非法 Base64 必须使当前调用失败。
- 同一业务连接、同一方向严格串行调用；同一连接的上行和下行可以并行，不同业务连接也可以并行，但受
  单软件包并发上限控制。第三方必须将所有方法实现为无状态、可重入，并保证相同输入被多次调用不会污染
  后续调用；Proxy 不自动重试任何处理 RPC，避免重复副作用。
- 业务连接在 RPC 期间关闭时，不发送取消 RPC；Proxy 释放本地并发额度并丢弃迟到响应。

### 超时、心跳、容量与错误语义

- 全局 RPC 超时默认 5 秒，设置范围 1..300 秒；第三方不能通过注册结果覆盖。超时的 frame/decode/encode
  使当前业务连接失败，不透明回退原始字节；display 超时或失败只记录错误并降级到 Hex，不影响线路转发。
- 每 10 秒发送标准 WebSocket Ping；连续约 30 秒没有 Pong 即认为连接断开。心跳独立于业务 RPC，慢调用
  不能阻塞 Ping/Pong。
- 每个软件包默认最多 256 个在途调用，可在设置中调整。达到上限不排队，新到业务连接立即以“软件包繁忙”
  失败，避免无界等待和内存增长。
- 注册消息最大 1 MiB；frame 和 Document 的逻辑大小复用现有请求体/报文限制，Base64 膨胀不计入逻辑大小；
  display HTML 最大 128 KiB。注册超限拒绝连接；低于 wire 上限但超过当前调用逻辑上限的响应只失败当前调用。
- 第一版基于 `tokio-tungstenite 0.30`：其公开异步 API 不支持在保留预读缓冲区的同时运行时修改 WebSocket
  配置。为避免注册后重建状态机丢失粘连帧，也不向未认证连接预先开放更大内存额度，整个连接的单条
  JSON-RPC wire message 固定为 1 MiB。逻辑 body/Frame 设置可以更大，但出站请求的有效 JSON 上限取逻辑上限与
  1 MiB wire 上限的较小值；超限时发送前返回 `MessageTooLarge`，只失败当前调用，软件包保持在线。入站消息
  超过 1 MiB 时 tungstenite 无法提供 response ID，Proxy 将其视为连接致命的 `MessageTooLarge`，关闭连接、标记
  软件包离线并停止引用入口。后续仅在上游提供安全动态配置 API 后再解除该传输层限制。
- 标准 JSON-RPC error 只失败当前业务连接，软件包保持在线，并将 `code/message` 及不含键和值的 `data`
  形状摘要关联到日志、抓包和 MCP 只读诊断；原始 `data` 不进入这些可观测面，避免泄露第三方密钥或内部状态。
  非法 JSON、错误响应 ID、重复响应或响应结构损坏属于协议失效：立即断开软件包、标记离线，并停止所有引用
  它的入口。

### 持久化与状态机

- SQLite 只保存注册元数据、规范化指纹、最近连接信息和用户启用状态；不得保存第三方代码、密钥、RPC 请求、
  RPC 响应、调用中状态或第三方内部状态。
- 第一次成功注册后状态为“在线 + 已停用”。用户必须在协议包页面显式启用，之后才可用于新入口。
- 在线/离线与启用/停用是两个独立维度：
  - 在线 + 启用：可供新入口选择，也可启动已绑定入口；
  - 在线 + 停用：保持连接，但不可选择或启动；
  - 离线 + 启用：保留配置和引用，但入口不可启动；
  - 离线 + 停用：仅保留元数据。
- 连接断开后立即标记离线并停止所有引用该精确版本的入口。相同版本重新连接后只恢复在线状态，不自动重启
  入口，用户必须重新检查并手动启动。
- 停用软件包时保持 WebSocket 连接，但停止所有引用入口并阻止重新启动。新入口选择器只显示“在线 + 启用”
  的外部软件包；已有离线/停用绑定仍显示精确身份和不可用原因，不自动替换。
- 被任何入口引用的软件包无论在线或离线都禁止删除。未被引用的软件包允许删除；若仍在线，Proxy 先关闭
  对应连接，再删除元数据。之后再次连接视为一次新的首次注册，默认停用。

### UI 与可观测性

- 设置页新增“外部软件包服务”，显示用途说明、实际 WebSocket 地址、固定路径、监听状态/错误、在线连接数、
  监听地址、端口、RPC 超时和单软件包并发上限，并明确“无身份验证，网络可达者均可注册”。
- 协议包列表继续统一展示内置协议包和外部软件包；外部项增加“外部”标志及在线/离线、启用/停用状态。
  详情展示远端地址、首次/最近连接时间、注册指纹、RPC 超时、方法映射、上下行字段结构、引用入口和最近错误。
- 外部软件包支持启用、停用和删除；引用中禁删原因必须可见。入口处理方案选择器明确区分“内置协议包”和
  “外部软件包”，且只列出当前在线并启用的精确版本。
- 抓包、运行日志和 MCP 必须能按软件包身份、连接、业务连接、方向、方法和 JSON-RPC 请求 ID 关联一次调用；
  不在普通 UI 暴露密钥或第三方内部状态。

### 架构与实施切片

1. **合同与领域模型**：定义严格注册 DTO、方法映射、外部软件包身份/指纹、在线与启用状态、typed Document
   JSON wire、frame/decode/encode/display 请求响应及稳定错误码；领域层不得依赖 WebSocket、SQLite 或 Tauri。
2. **应用端口与用例**：新增外部执行后端端口、目录查询、启停删除、断线联动和入口可启动性检查；规则、抓包和
   Document 继续复用现有应用模型，不复制外部专属业务规则。
3. **基础设施**：实现单 WebSocket 服务、JSON-RPC 请求关联、30 秒注册、Ping/Pong、并发额度、超时、迟到响应
   丢弃、SQLite 元数据仓储和断线停止入口。网络 actor 与数据库仓储隔离，禁止让 Socket 转发核心直接依赖 UI/DB。
4. **Socket 运行时适配**：把外部后端接入现有四阶段/本机应答处理链，保持同方向顺序、双向并发、粘包拆包、
   half-close、写失败前缀和 capture generation 语义。
5. **Tauri/前端**：新增严格 IPC DTO/commands、设置页服务状态、协议包统一目录与详情、入口选择和启停/断线提示；
   生成绑定，不手写前后端重复类型。
6. **扩展预留**：执行后端使用统一端口和 backend identity，使后续可把单个 backend 选择升级为有序 backend chain；
   第一版不得提前实现链式 UI、隐式 fallback 或无实际需求的兼容分支。

### 验收测试

- 注册合同覆盖成功、30 秒超时、未知键、缺失方法、空/重复 Schema 字段、非法方法后缀、同命名空间方法冲突、
  相同身份重复在线、相同身份指纹变化、不同版本/不同软件包同时在线和 1 MiB 边界。
- 真实 WebSocket + JSON-RPC + TCP 覆盖拆包、粘包、一次缓冲多帧、上下行独立 Schema、四阶段规则、本机应答、
  DUKPT 类“frame 看密文边界、decode 解密、encode 加密”测试替身，以及 display HTML/Hex 降级。
- 覆盖同方向严格顺序、双向并发、不同连接并发、256 容量边界、繁忙立即失败、慢调用期间心跳正常、三次心跳
  丢失、调用超时、业务连接提前关闭和迟到响应丢弃；测试不得依赖 sleep 竞争，应使用受控时钟/Barrier。
- JSON-RPC 标准错误只关闭当前业务连接；非法 JSON、错误 ID、重复响应和结构损坏必须断开软件包并停止绑定入口。
  frame/decode/encode 失败不得透明转发，display 失败不得中断成功转发。
- 状态机覆盖首次注册默认停用、启用、停用、断线、重连不自动重启、离线保留、精确版本选择、已有绑定不可用、
  引用中禁删、在线未引用删除会主动断开，以及应用重启后只恢复元数据不伪造在线状态。
- 验证 SQLite 和 IPC 均使用 strict current schema，无旧版本兼容或静默 fallback；数据库失败不产生内存/持久化
  状态分裂，断线/停用和入口停止结果可在日志、抓包、MCP 与 UI 中关联。
- 前端覆盖设置、列表、详情、启停、删除、入口选择、离线/停用提示、窄窗口、键盘和屏幕阅读器；外部软件包
  相关新增/重写核心模块目标行/分支/函数覆盖率均不低于 90%，注册状态机和 closed union 分支目标 100%。
- 最终在 macOS 与 Windows 产物上使用至少两个并发第三方测试进程完成注册、启用、绑定、处理、断线、重连和
  删除流程；验证内置协议包不受外部服务绑定失败或第三方崩溃影响。

### 明确不做

- 第一版不支持 HTTP 外部软件包、不支持外部与内置处理链组合、不支持自动重试、自动升级、自动重连入口、
  自动备用软件包、认证授权、远程下载安装第三方程序或由 Proxy 管理第三方密钥。
- 不为尚未发布的旧实验格式增加兼容解析；注册、数据库和 IPC 只接受本任务定义的当前合同。
